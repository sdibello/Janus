# Alpha 0.1 implementation tasks

Source: [Alpha changes](Alpha-changes.md). The alpha 0.1 encounter workflow is implemented and verified on Windows.

## Review

The requested initiative lightbox replaces initiative entry and tie ordering during Prepare in [spec 004](../specs/004-initiative-and-turn-sequence.md). Moving a completed tile to the bottom **changes the saved Fight order**, which replaces the fixed-list traversal assumed by [spec 005](../specs/005-manual-encounter-order.md). The counter and active-selection rules are confirmed in decision 0079. Keep whole-number initiative, optional HP, individual Turn behavior, authorization, and persistence unless explicitly changed.

The confirmed behavior is recorded in [decision 0079](../decisions/0079-alpha-encounter-workflow.md). Begin Fight prompts for initiative **one participant at a time**; after the last entry, the DM reviews the initial order and explicitly confirms Fight. Equal values keep encounter entry order. Closing the lightbox returns to Prepare and retains partial entries; existing saved initiative values prefill it. Prepare participant rows start collapsed.

During Fight, the tile view starts at the active participant. Next and Skip move that top tile to the bottom and **save the resulting order**. Round increments after every participant in the current Round has used Next or Skip once; Skip does not increment that participant's Turn counter, and a participant added during Fight joins the current Round. Set active does not reorder the saved list; a drag saves only the chosen order, with no extra rotation. The tile view must still put the active participant first. The focused encounter screen also applies to Finished encounters, with a Back to campaign control. The tie rule supersedes the manual Prepare tie ordering in [decision 0023](../decisions/0023-manual-initiative-ties.md).

No product questions remain for this alpha task list. Row expansion can remain local UI state; the saved encounter data is unaffected.
