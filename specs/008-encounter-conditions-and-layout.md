# 008: Encounter conditions and layout

- Status: Accepted for local implementation
- Date: 2026-09-28
- Source: [02 changes](../docs/02-changes.md) and follow-up answers
- Related decision: [0083](../decisions/0083-encounter-conditions-and-layout.md)

## Prepare

- The add-participant card remains open. Its fields and buttons use the same form styling as the Fight cards.
- **Add All** adds every campaign PC and NPC absent from this encounter. It does not set HP or disturb existing participants. PCs are appended first, then NPCs, each by name; repeated use adds nothing.
- Participants appear as rows with an inline Remove button. Selecting a row reveals its optional Current HP editor. Only one row is selected at a time.
- Active and held Prepare rows show the same small PC, NPC, or Mob badge used in Fight, immediately before the participant name. There is no separate type label beside the name. See [decision 0088](../decisions/0088-campaign-character-renaming-and-prepare-badges.md).

## Fight

- Hold appears in a right-hand column on displays at least 1600px wide. The turn-order list keeps its existing maximum 1120px width; Hold occupies 25% of the combined column widths, excluding the gap. Below that breakpoint, Hold stacks underneath without shrinking the participant list. The whole panel accepts participant drops, even when empty, with visible drag feedback. Held participants appear as compact name-only boxes; drag one back to an insertion slot or the empty turn order to release it. Selecting a name also releases it at the end, including by keyboard. Fight rows have no Hold button; drag the participant into Hold or use Alt+H on its focused tile. Prepare and Finished retain their detailed Hold lists above participants. See [decision 0094](../decisions/0094-fight-hold-sidebar.md); this replaces the Fight Hold placement in the next bullet.
- The Hold heading and count share one line with a help icon whose hover title explains Hold and release; an empty Hold list shows its empty message on that line. Turn order has a help icon with drag-and-keyboard instructions in its hover title. **Add Participant** and **End encounter** sit beside Turn order. Add Participant opens a dialog with the existing PC, NPC, and mob forms; after a successful add, the dialog closes. Prepare keeps the add forms visible. See [decision 0087](../decisions/0087-fight-section-headers-and-add-dialog.md).
- Every Fight card, including the active participant, uses one compact heading row with aligned name/Turn, HP, and action groups. Only the active participant has an additional row below the heading, with Next/Skip and summaries of the impacts of its applied statuses. The summaries include HP-derived state, deduplicate identical manual/derived conditions, and show a no-status message when appropriate. Other cards remain compact. There is no Active turn bubble; the active outline and accessible active-participant label with aria-current identify the current participant. Name, HP, and action/status groups use proportions 1.5:2:1, giving names about one third of the row and shifting HP controls right. Names stay on one line and truncate with an ellipsis; a tooltip shows the full name. The same truncation applies to compact held-name boxes. See [decision 0097](../decisions/0097-top-drop-activation-and-inline-fight-controls.md).
- No Fight card has a Set active button or icon. Drop a participant above the current active participant to move it to the top and make it active in one saved operation. Drops elsewhere keep the current active participant. A held participant released into the top slot becomes active. Alt+Home on a focused Fight card performs the same top move and activation; Alt+Up crossing into the top slot does too. Failed saves retain saved order and active selection; no turn counters advance.
- HP controls appear in this order: current HP display/edit icon (or Current HP editor with Save/Cancel), four-character adjustment textbox, Damage, Heal. The adjustment textbox sits directly before Damage on every card. Adjustment input and Damage/Heal are 30px tall. Input width remains a presentation choice, with existing numeric validation and capacity. Controls can wrap within their groups and groups stack on narrow screens.
- A searchable, scrollable Statuses box below Hold lists 42 D&D 3.5 statuses: all 38 SRD condition-summary entries plus the four existing project-reference tags Dehydrated, Diseased, Poisoned, and Rebuked. Labels, short summaries, and rule links come from the shared catalog used by the API. See [decision 0099](../decisions/0099-dnd35-condition-catalog-and-active-summary.md) and [the researched reference](../docs/status.md). Drop a status onto an active or non-active turn-order participant to apply it; a valid target is highlighted. Status drags must never trigger reordering or Hold/release. For keyboard access, select a status and press Enter or Space on a focused participant; Escape clears the selection. There is no per-row status-picker button or status dialog. See [decision 0095](../decisions/0095-draggable-status-palette.md). Multiple statuses may coexist. Each appears in a right-aligned bubble with an × removal control. Reapplying an existing status has no effect. Adding or removing a status does not change active participant, order, or counters.
- Each applied status starts at 0 turns and shows the number of that participant's **Next** actions while applied. Skip does not increase it. Status and count survive reopening; status bubbles are shown only in Fight, and finished encounters offer no editing controls. Removing and reapplying starts a new count at 0. No game-mechanical effects are automated.
- HP-derived Disabled, Dying, and alive adjacent bubbles appear in the right-aligned status group alongside manual statuses, retaining their yellow/orange/muted-red badge colors. They no longer appear in the HP group. See [decision 0098](../decisions/0098-fight-name-space-and-status-alignment.md). At 0 HP show Disabled with a yellow card. For negative HP above -10 show Dying with an orange card. At -10 or below retain alive adjacent. Changes to HP recalculate this derived label and color; all participants remain in turn order.

## Campaign overview

- Hide Local services on the Campaigns page. Place Encounters below Your campaigns in the left column.
- Show active Fights first, then Prepare encounters. Finished encounters start in a collapsed group and can be expanded for viewing.

## Layout validation

`web/tests/encounter-flow.mjs` includes rendered-position assertions for non-active columns with different name lengths, saved/unset HP, and opening, saving, and canceling HP edits. It also checks the inline active HP/turn actions after a turn change, disabled Damage/Heal with unset HP, and stacked groups without horizontal page overflow at a 640px viewport. Those account-backed assertions have not yet been rerun. `web/tests/hold-sidebar.mjs` tests the built UI with isolated API fixtures for sidebar widths, compact tiles, drag/release, errors, empty-order release, keyboard release, reload, and Prepare/Finished layouts. It also covers the shared status palette, new catalog conditions and effect summaries alongside the three legacy statuses, applying statuses to active/non-active participants, preserving existing status counts on duplicate drops, rejected condition saves, removal, reload, keyboard apply/Hold, and ignoring a status dragged into Hold. See [local development](../docs/LOCAL-DEVELOPMENT.md) for commands and validation status.

The isolated sidebar check passed with headless Chromium on Fedora 44 on 2026-10-17. It verifies UI behavior with fixture responses, including unchanged HP, conditions, Round, and individual Turn values through Hold/release. It does not establish backend persistence or authorization.

These rules supersede the old Unconscious/zero-HP and collapsed Prepare-row presentation in [spec 007](007-hit-point-tracking.md), and the earlier deferral of all manual statuses.
